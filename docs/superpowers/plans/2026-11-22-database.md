# Slice 2 Database Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship reviewed Supabase migrations, seed data, locked-down privileges, `hold_seats`, and database tests for the demo — without pushing until the showbuyer says so.

**Architecture:** Postgres schema mirrors `spec.md` types. The Next.js server is the only client (service role). `hold_seats` serializes work per showbuy with `FOR UPDATE` on the showbuy row, then holds one choice atomically using a server-supplied quote.

**Tech Stack:** Supabase Postgres 17, SQL migrations, `supabase/seed.sql`, pgTAP under `supabase/tests/database`, local `config.toml` auth flag.

**Spec:** `docs/superpowers/specs/2026-11-22-database-design.md` (implements `spec.md` data layer)

## Global Constraints

- Money in centavos; never real buyer/payment/seat-plan data
- RLS on every table; no anon/authenticated policies or privileges
- Functions: `search_path = ''`; execute only for `service_role`
- AI / server never sets Paid; hold starts at `sent_payment_info`
- Do not run `supabase db push` or config push until explicitly asked
- No new libraries without asking

## Review Focus

- Cross-showbuy FK slip (section/payment/seat from another showbuy) → reject inside `hold_seats` and via composite FKs
- Idempotent retry with same key after partial client timeout → return same order, no double hold
- Cancel after `payment_confirmed_at` set → CHECK rejects
- SINGLE with aisle gap (missing neighbor seat) → gap is not a neighbor
- Quote/total mismatch vs held qty → reject before write
